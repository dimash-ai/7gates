# Combined design — focal-parity slice 4 (Tasks editor/filters parity)

3-gate A artifact (folds think + plan + design). Full think/plan also exist at
`.ai/think/focal-parity-tasks.md` (APPROVED 9.4) and `.ai/plans/focal-parity-tasks-plan.md`

## 1. Problem & assumptions (think)

**Problem.** The new Tasks page is read + quick-add + delete + complete-toggle only: the edit pencil
is hardcoded `disabled`, there is no create/edit dialog (`TaskDialog`), no detail dialog
(`TaskInfoDialog`), the "Filter" button toggles nothing, and there is no schedule-to-calendar or
inline tag-create. old-focal `components/TaskDialog.tsx` + `TaskInfoDialog.tsx` + `pages/Tasks.tsx`
are the binding spec. This slice consumes the already-merged foundations: **slice 2** put
`canEdit`/`dataOwnerId` gating + `calendarId` scoping on `TasksPage` and `api/tasks.ts`; **slice 3**
added the timezone provider (tasks use wall-clock `dueDate`/`dueTime`, so tz conversion is N/A for
due times, but the schedule-to-event payload must carry the display timezone).

**The one backend gap.** old-focal's task editor sets **recurrence** (`none|daily|weekly|monthly|
yearly`) and **multi-participant** (`contactIds[]` + `otherParticipants`); the new task model/schema
has only a single `contact_id` and no recurrence/other_participants (`models/tasks.py`,
`schemas/tasks.py`). Everything else the editor sets — title, description, due_date, due_time,
project/product/activity, tags, status/completed — already exists. (old-focal removed manual
priority; the dialog has **no** priority control.)

**Assumptions.**
- [confirmed — schema] only recurrence + multi-participant are missing backend-side; all other dialog
  fields exist. Single `contact_id` today.
- [confirmed — slice 2] `canEdit`/`currentCalendarId` already on `TasksPage`/`api/tasks.ts`; the new
  dialog/filters/actions must consume them (disable + early-return on `!canEdit`; thread `calendarId`
  through every task/tag/project/activity/event call).
- [confirmed — slice 3] timezone foundation (`useTimezone` → `displayTimezone`) exists.
- [confirmed — source] the new `eventsFilters.ts` (`focal-events-filters`, soft `all→thisMonth`,
  single→array migration) is a faithful old-focal filter port and the exact mirror for `tasksFilters`.
- [confirmed — repo rules] the recurrence/multi-participant model + Alembic migration is
  **developer-owned / interactive Claude Code under the user's review** (unattended agents edit models
  only); target = local Docker PG, applied manually after merge.
- [no Tasks-page drag reorder] the old Tasks page is a sorted list (`taskSort`); the draggable
  `TaskItem` is the **calendar** task panel (slice 6).

**Options.** A — 4a frontend-only (editor + filters + schedule + tag-create over existing fields),
then 4b backend handoff (recurrence + participants migration + wire controls). B — backend-first,
one slice (couples migration risk with the big UI; rejected). C — drop recurrence+participants
(breaks parity; rejected). **Recommendation: A** (mirrors slice 2's 2a/2b split).

**Out of scope.** AI-assistant button (slice 12), offline/optimistic (slice 11), drag-onto-calendar
(slice 6), manual priority, event custom-recurrence intervals, auth/landing.

**Open questions (now resolved here).** schedule event field is `timezone` (value = `displayTimezone`)
— see Interfaces; `all→thisMonth` is source-traced (mirror `eventsFilters.ts`) — keep; keep legacy
`contact_id` for back-compat in 4b.

**Success criteria.** Tasks page matches old-focal (create/edit dialog, detail dialog + actions,
working filter/search panel with persistence, schedule-as-event, inline tag-create — all
`canEdit`-gated + `calendarId`-scoped); 4b adds recurrence + participants via model + autogenerated
Alembic migration (`alembic check` clean) + `gen:api`; each sub-slice green on the client (and 4b on
the backend); ru+en; surgical.

## 2. Plan in slices

**4a (frontend-only, shippable):**
- **4a.1 `tasksFilters.ts` + test** — pure filter model mirroring `eventsFilters.ts`: `STORAGE_KEY =
  'focal-tasks-filters'`, `DEFAULT_FILTERS`, load/save (single→array migration, invalid preset →
  `thisMonth`, soft `all→thisMonth` unless another filter active, corruption-safe), option derivation,
  `getTaskQueryRange` (date-preset → `listTasks` window), task predicates (search; projectType; sphere;
  project; product; activity; tag incl. `no-tag`; date presets incl. custom; future presets keep
  undated tasks), active-count, reset. *Test proves:* defaults/migration/corruption-safety, query
  window per preset, each predicate, no-tag, reset preserves header selects, active count ignores them.
- **4a.2 `TaskDialog.tsx`** — create/edit over existing fields (title, due date + time, project→
  product→activity cascade reset-on-change, single tag + inline create-with-color, notes); schedule-
  as-event for existing dated tasks; disabled while saving; never closes on mutation error. No
  recurrence/participant controls (4b). *Failure modes:* blank title (submit guard), save reject
  (dialog stays open, draft kept), tag-create reject (form stays open).
- **4a.3 `TaskInfoDialog.tsx` + `TasksPage` wiring** — detail view (edit/delete/complete/inline-date),
  Add button + row pencil open `TaskDialog`, row opens info; keep Active/Completed grouping,
  `compareTasksForDisplay`, orphan badges, color stripes; every mutation handler `if (!canEdit) return`
  and controls disabled when `!canEdit`; `calendarId` on all calls; invalidate `['tasks']` (+`['events']`
  on schedule). *Failure modes:* list/save/delete/toggle/inline-date reject → localized error, no
  optimistic overwrite.
- **4a.4 Filter/search panel** — replace the inert button with a panel over `tasksFilters`; options via
  `listProjects/listActivities/listTags(currentCalendarId)`; option-query failure → small localized
  panel error, rows stay usable; filtered-to-zero keeps the list (not the "no tasks yet" empty state).
- **4a.5 verify** — locale keys (ru+en), expand `TasksPage.test.tsx`, run client lint/typecheck/
  test:run/build.

**4b (backend handoff, developer-owned):**
- **4b.1** model `recurrence: String(20)|None` (default `none`), `contact_ids: JSONB|None` (default
  []), `other_participants: Text|None`; **keep `contact_id`**; autogenerated additive Alembic migration
  (reviewed, reversible); schemas (`recurrence` enum of 5; `contactIds[]`; `otherParticipants`;
  `contactId` legacy input alias, read keeps `contactId`); service persist/read incl. legacy
  `contact_id`→`[contact_id]` fallback; DB + contract tests; `make verify` + `alembic check`.
- **4b.2** `pnpm gen:api`; wire recurrence select (5 values) + participants CRM(`ContactPicker` multi →
  `contactIds`)/Other(textarea → `otherParticipants`) toggle into `TaskDialog`; show in `TaskInfoDialog`
  when present; tests; both verify sets.

## 3. Design

### Architecture

```
TasksPage (orchestrator; consumes useCalendarFilter → canEdit/currentCalendarId, useTimezone)
 ├─ tasksFilters.ts (pure: load/save/derive/filter/range/count) ← localStorage focal-tasks-filters
 ├─ FilterPanel (inline in TasksPage; options from listProjects/listActivities/listTags(calId))
 ├─ TaskDialog (feature-local; create/edit; project→product→activity; tag + inline create; schedule)
 └─ TaskInfoDialog (feature-local; read + edit/delete/complete/inline-date)
        all mutations → existing api/tasks|tags|events wrappers (calendarId threaded), React Query
4b: server models/tasks → schemas/tasks → services/tasks → migration; client api/openapi.d.ts (gen:api)
```
Coupling: dialogs are feature-local (no shared-primitive churn); filter logic is pure + unit-tested;
`TasksPage` owns state + mutations. Reuse: `compareTasksForDisplay`, `getDateRangeFromPreset`/
`getRestRangeFromTodayYmd` (`lib/datePresetRange`), `eventsFilters.ts` as the filter template, the
existing typed API wrappers (all already accept `calendarId`), PRIMA `ContactPicker` (4b), shadcn
primitives + native `input[type=date|time]` (no new date-picker dep, no dnd-kit).

### Data model

| entity | change | notes |
|--------|--------|-------|
| localStorage `focal-tasks-filters` | add (client) | filter state; single→array migration; soft `all→thisMonth` (mirrors `eventsFilters.ts:74,118`); corruption-safe load |
| `focal.tasks.recurrence` | **4b add** | `String(20)`, nullable, app default `none`; read normalizes NULL→`none` |
| `focal.tasks.contact_ids` | **4b add** | `JSONB`, nullable, app default `[]`; read normalizes NULL→`[]` |
| `focal.tasks.other_participants` | **4b add** | `Text`, nullable |
| `focal.tasks.contact_id` | **keep** | legacy single; read still exposes `contactId`; service falls back `contact_id`→`[contact_id]` when no list |
| migration | **4b add** | autogenerated, **additive + reversible**, `alembic check` clean; no hand-authored backfill |

### Interfaces & contracts

**`TaskDialog`** — `{ open; onOpenChange; task?: Task|null; onSave(payload); onScheduleAsEvent?(task);
saving; canEdit }`. **4a save payload** (existing fields only): `{ id?, title, description?, dueDate?,
dueTime?, tags: string[], projectId?, productId?, activityId?, completed }` — **never** sends
`recurrence`/`contactId`/`contactIds`/`otherParticipants` (so editing preserves any existing backend
`contactId`, since `TaskUpdate` omitted = preserve). 4b adds `recurrence` + `contactIds`/
`otherParticipants` to the payload.

**`tasksFilters.ts`** — `loadTaskFilters(): TaskFilters`, `saveTaskFilters(f)`,
`filterTasks(tasks, f, ctx): Task[]`, `getTaskQueryRange(f): {startDate?, endDate?}`,
`deriveTaskFilterOptions(projects, activities, tags)`, `activeTaskFilterCount(f)`, `DEFAULT_FILTERS`,
`STORAGE_KEY`. Shapes/semantics mirror `eventsFilters.ts` 1:1 except the **task date predicate**
(future presets keep undated tasks; past/custom require a due date in range; `all` = no date predicate).

**Schedule-as-event mapping** (resolves plan Should-Considers #1/#2) — enabled only when `canEdit` &&
`task.dueDate`. Build `EventCreate`:
`{ title: task.title, description: task.description, date: task.dueDate (YYYY-MM-DD),
startTime: task.dueTime || '09:00', endTime: <startTime + 1h>, projectId/productId/activityId from
task, status: 'planned', completed: false, recurrence: 'none', timezone: displayTimezone }` — the
field is **`timezone`** (NOT `displayTimezone`; that's the value from `useTimezone()`); `extra="ignore"`
would silently drop a wrong key. `createEvent(payload, currentCalendarId)`; **on success delete the
source task** (old-focal task→event conversion). Pin the `endTime` default against old-focal at build
if it differs from +1h.

**4b schema additions** — `recurrence` accepts `none|daily|weekly|monthly|yearly` (create-omit →
`none`; update-omit preserves; update `"none"` clears; update `null` → 422). `contactIds: string[]`
(create-omit → `[]`; update-omit preserves; `[]` clears; `null`/non-string → 422). `otherParticipants:
str|None` (clearable with `null`). `contactId` accepted as legacy input only when `contactIds` omitted;
read responses keep `contactId`.

### Flow (happy + unhappy)

| path | trigger | handled where | result |
|------|---------|---------------|--------|
| happy — create/edit | Add / pencil → dialog → save | `TaskDialog` → `createTask`/`updateTask(calId)` | invalidate `['tasks']`; dialog closes |
| happy — schedule | dated task → schedule | dialog → `createEvent(calId)` then `deleteTask` | event created, task removed; invalidate tasks+events |
| read-only | `!canEdit` (shared calendar) | every handler `if(!canEdit) return` + disabled UI | no write fires; reads render |
| list load fails | `listTasks` rejects | page query error branch | localized page error; filter shell usable |
| filter-options fail | `listProjects/Activities/Tags` reject | panel option branches | localized compact panel error; rows + working filters remain |
| filter storage read/write fails | localStorage throws | `loadTaskFilters`/`saveTaskFilters` catch | defaults / in-memory; no banner |
| save / delete / toggle / inline-date fails | mutation rejects (`ApiError`) | mutation `onError` | localized error; draft kept; no optimistic overwrite |
| tag-create fails | `createTag` rejects | inline mutation `onError` | localized inline error; form stays open |
| schedule create fails | `createEvent` rejects | before delete | localized error; task untouched |
| schedule delete fails (after create) | `deleteTask` rejects post-create | second step | localized **partial-conversion** error; event + task both kept (no silent loss) |
| filtered-to-zero | filters hide all rows | render | keep list (not "no tasks yet") |
| 4b recurrence/contactIds invalid | Pydantic 422 | schema validation | dialog stays open, shows save error |
| 4b migration drift | `alembic check` | 4b verify | gate blocks until model↔migration match |

### Alternatives rejected
- **Backend-first one slice (B)** — couples migration + `gen:api` risk with the big UI; blocks the
  visible win. **Drop recurrence/participants (C)** — breaks parity. **Tasks-page drag reorder** — not
  an old-focal Tasks-page behavior (sorted list; draggable `TaskItem` is the calendar panel, slice 6).
- **Squeeze multi-participant through the single `contact_id` in 4a** — rejected; participants wait for
  4b's real `contactIds[]`, and 4a omits the field so existing values aren't clobbered.

### Test strategy
- **Unit** (`tasksFilters.test.ts`): defaults/migration/corruption, query-range per preset, every
  predicate + no-tag + future-keeps-undated, reset + active-count semantics.
- **Component** (`TasksPage.test.tsx`): open create/edit, payload omits recurrence/participants in 4a,
  `canEdit` gates every write (no API call when false), `calendarId` threaded through all wrappers,
  info-dialog actions, filter panel + persistence + remount, filter-options failure, inline tag-create,
  schedule-as-event (incl. `timezone` field) + partial-failure, load/mutation error surfaces.
- **4b backend** (`test_tasks_db.py`/`test_contracts.py`): recurrence default/validation/round-trip,
  contactIds + otherParticipants create/update/clear, legacy `contact_id` fallback, response shape pin;
  **4b component**: recurrence + participants controls send the new fields, no stale inactive-mode value.
- **"Verified"** per sub-slice: client `pnpm lint && pnpm typecheck && pnpm test:run && pnpm build`
  green; 4b also `make verify` + `uv run alembic check`.

### Security & release notes
- **Client scoping is not security** — slice-2 backend RBAC + RLS enforce shared-calendar access;
  `canEdit`/`calendarId` are UX/scoping. 4a tests assert no write fires when `!canEdit`, but the
  guarantee is server-side.
- **4b migration** is additive + reversible (new nullable columns + legacy column kept); ships with the
  model change; `alembic check` gates drift; applied manually to shared envs after merge.
- No secrets/PII in client, tests, or PR text. 4a rollback = revert client files; 4b rollback = revert
  wiring + the additive migration/model/schema/service before it is applied to shared envs.
