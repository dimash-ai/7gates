# Summary

Build the Focal foundation on top of the existing scaffold in `superapp/apps/focal/server` in five
small, independently-green slices: (1) lockfile refresh + `make verify` harness, (2) Alembic async
config for `focal.*`, (3) the auth verifier + `users` shadow model + heal (added alongside the demo
path), (4) swap the demo dependency to real auth — server **and** the client Bearer handoff, (5) `/me` +
lifespan JWKS warm + `/health` hardening. The auth module is authored Focal-local (PyJWT + cached JWKS,
ES256), modelled on legacy `focal/server/auth.ts` semantics and the [AUTH_FLOWS.md](../../superapp/docs/AUTH_FLOWS.md)
contract — but with local JWKS verification instead of `supabase.auth.getUser` (no per-request network
call). Task: [focal-foundation.md](../tasks/focal-foundation.md).

## Decisions (resolving the Gate-1 Should-Considers)

- **`focal.users.id` is value-equal to `auth.users.id`, NOT a hard DB foreign key.** `auth.users` lives
  in Supabase's managed `auth` schema; a cross-schema FK would couple `focal.*` migrations to it and
  break the empty-DB Alembic verification (the `auth` schema isn't present in a bare test DB). The id is
  a UUID PK set from the JWT `sub` by the heal, equal by application convention (matches migration-plan
  §6.2). Trade-off: a deleted Supabase user can leave an orphan `focal.users` row — acceptable for the
  foundation (heal is best-effort identity continuity); revisited in the data-migration workstream (§6).
- **`AuthRequiredError` codes/messages are fixed** so tests assert them, not infer: missing/empty Bearer
  → `code="auth_required"`, `message="Authentication required"`; any verification failure (expired,
  malformed, wrong alg/aud/iss, missing exp/sub, unresolvable kid) → `code="invalid_token"`,
  `message="Authentication failed"`. Messages are generic (no token/claim detail). The exception class
  **already exists** at `superapp/apps/focal/server/app/errors.py:39` — reuse it, don't redefine.
- **PII-in-logs rule:** the opaque `sub` (user UUID) **may** be logged as `user_id` for correlation
  (matches the superapp structlog/correlation standard); the raw token string, `email`, and names must
  **never** be logged.

# Implementation slices

Each slice is independently reviewable (gate-code → fix loop) and leaves `make verify` green.

1. **Dev-deps group + lockfile check + `make verify`.** Move dev tools (ruff/mypy/pytest/pytest-asyncio)
   from `[project.optional-dependencies] dev` to a PEP 735 `[dependency-groups] dev` so plain `uv sync`
   installs them (else a fresh checkout can't run the harness); `uv.lock` already exists — `uv sync
   --frozen` to check it matches `pyproject.toml`, regenerate (`uv lock`) and commit **only if** drifted.
   Add `Makefile`: a `db-up` target (`docker compose -f ../docker-compose.yml up -d`) and `verify: db-up`
   that exports `DATABASE_URL` + `REDIS_URL` (local Docker PG on 5433 / Redis on 6380) then runs
   `uv run ruff check . && uv run ruff format --check . && uv run mypy app && uv run pytest`, so DB-backed
   acceptance tests **run rather than skip**. No behavior change. Verify: on a fresh `uv sync --frozen`,
   `make verify` is green with dev tools present and DB tests executed.
2. **Alembic async config for `focal.*`.** Add `alembic.ini` + `env.py` (mirror prima:
   `async_engine_from_config`, `run_sync(do_run_migrations)`, `version_table_schema="focal"`,
   `include_schemas=True`, `target_metadata = Base.metadata`) **plus two safety additions prima lacks:**
   (a) an `include_name` callback restricting reflection/compare to the `focal` schema (so autogenerate
   never emits `DROP` for `prima.*`/`auth.*`/`billing.*` in the shared DB), and (b)
   `CREATE SCHEMA IF NOT EXISTS focal` executed before `run_migrations` (so `alembic upgrade head` works
   on a truly empty DB, not only one pre-seeded by `db/init.sql`). Add `script.py.mako` (copied from prima
   — `alembic revision` requires it); make `app/models/__init__.py` import every model. Verify (developer):
   `alembic revision --autogenerate` produces a baseline creating the `focal.*` tables **and nothing in
   other schemas**; `upgrade head` on an empty DB; `alembic check` clean.
3. **Auth module + `users` model + heal (additive — demo path still present).** Add `app/auth.py`
   (`verify_jwt`: PyJWT, ES256-pinned, `audience="authenticated"`, issuer `{normalized SUPABASE_URL}/auth/v1`,
   `require=[exp,iss,sub]`). JWKS handling is **explicit** because `PyJWKClient` is synchronous:
   `PyJWKClient(jwks_url, cache_keys=True, timeout=SUPABASE_JWKS_TIMEOUT_S)`. Per-request key lookup
   (lazy / unknown-`kid`) runs as
   `await asyncio.wait_for(asyncio.to_thread(client.get_signing_key_from_jwt, token), SUPABASE_JWKS_TIMEOUT_S)`;
   the **startup warm is token-free** —
   `await asyncio.wait_for(asyncio.to_thread(client.get_jwk_set, refresh=True), SUPABASE_JWKS_TIMEOUT_S)` —
   both off the event loop and bounded (per-request timeout → `AuthRequiredError`; warm timeout/failure →
   logged, non-fatal). **Reuse**
   `AuthRequiredError` with the fixed codes; reads `app_metadata.tier` only. Add `app/models/users.py` +
   `heal_user_identity` (synchronous inline, `INSERT … ON CONFLICT DO NOTHING`, try/except-logged
   best-effort). Add `tests/conftest.py` JWT fixture + `tests/test_auth.py`. Verify: the full auth matrix +
   the cache/rotation tests pass; demo path untouched so all prior tests stay green.
4. **Swap demo → real auth (server + client).** Server: point `app/deps.py` at `get_current_user`; the
   route passes `current_user.id` (a `str`) to the **unchanged** tags service (`user_id: str`); rewire
   `/api/tags` + its server tests to the JWT fixture. `X-Demo-User-Id` is removed from the default path and
   survives only behind an explicit `FOCAL_DEMO_AUTH` env flag (off by default; for the local dev loop +
   the existing demo tests) — the task's env-gated-bypass allowance. **Client (Bearer attach):** add
   `client/src/api/session.ts` `getAccessToken()` returning the **host-provided shared-session token**
   (Supabase issues it; the client only attaches it — **never mints or signs**, per AUTH_FLOWS.md); change
   `client/src/api/tags.ts` to send `Authorization: Bearer <token>` when a session token is present instead
   of `X-Demo-User-Id`; update `tags.test.ts` to stub `getAccessToken()` + assert the header, and drop
   `VITE_DEMO_USER_ID` from `client/.env.example`. Standalone-dev
   (pre-shell) has no shared session, so the local Tags page runs against the server with
   `FOCAL_DEMO_AUTH=1`; the real shared-session source arrives with the shell (SHELL_CONTRACT.md). Verify:
   server tags tests pass under real auth; the default path rejects `X-Demo-User-Id`; client tags tests
   pass with the Bearer header.
5. **`/me` + lifespan warm + `/health` hardening.** Add `app/api/me.py` (read-only id/email/tier behind
   `get_current_user`); wire JWKS warm into the lifespan (non-fatal on failure); add per-probe ~1s
   timeouts + `{db,redis,r2}` flags to `health.py`. Verify: `/me` + `/health` tests; `make verify` green.

# Tests

- **Auth matrix** (`test_auth.py`, integration via httpx + the ES256 fixture): valid → user; `user_metadata.tier`
  ignored → `free`; expired / malformed / wrong-alg / wrong-aud / wrong-or-missing-iss / missing-exp-or-sub
  → `AuthRequiredError("invalid_token")`; missing header → `AuthRequiredError("auth_required")`. *Proves the
  verifier rejects every bad token and never trusts user-controlled metadata.*
- **JWKS cache / no network** (patch the JWKS fetch with a call counter): after warm, N repeated valid
  requests trigger **exactly one** fetch. *Proves the steady-state acceptance criterion — no per-request
  network call.*
- **JWKS rotation** (fixture rotates the signing key): unknown-`kid` + the fake JWKS now serving the new key
  → token **accepted** (one extra fetch); unknown-`kid` + a refresh that times out → `invalid_token`,
  returning within ~`SUPABASE_JWKS_TIMEOUT_S` (no indefinite hang). *Proves rotation works and the bounded
  refresh never blocks or fails open.*
- **Startup warm**: a failing initial JWKS fetch does not crash startup; the first request still authenticates
  via lazy fetch. *Proves warm-failure is non-fatal.*
- **Heal** (DB-backed): first authed request creates `focal.users` (id == `sub`); concurrent first-requests →
  one row, no error; a forced upsert failure still returns 200 and `/me` serves claims. *Proves idempotent,
  deterministic, best-effort heal.*
- **`/me`**: returns id/email/tier for a valid token; 401 without one.
- **`/health`**: 200 with `db`/`redis` flags; a stubbed-down dependency yields `"error"` within the probe
  timeout (no hang) while the endpoint stays 200.
- **Logging**: assert no token string / email appears in captured logs on the failure paths (`user_id` is allowed).

> DB-/Redis-backed tests (heal, tags, real `/health`) require `DATABASE_URL` + `REDIS_URL` and `skip` when
> absent — which would let `make verify` go green without proving them. So the Makefile's `verify` target
> brings up `docker compose` and **exports both `DATABASE_URL` and `REDIS_URL`** (slice 1), guaranteeing
> these tests **execute, not skip**. The heal concurrency/upsert tests are the proof of that behavior and
> must run under `make verify`.

# Error & rescue map

| failure mode | error / exception | caught where | what the user sees |
|--------------|-------------------|--------------|--------------------|
| Missing/empty Bearer | `AuthRequiredError("auth_required")` | `get_current_user` → AppError handler | 401 `{error:{code:"auth_required",message:"Authentication required"}}` |
| Expired / malformed / wrong alg/aud/iss / missing exp/sub | `AuthRequiredError("invalid_token")` | `verify_jwt` → handler | 401 `{error:{code:"invalid_token",message:"Authentication failed"}}` |
| Unknown `kid`, bounded refresh returns key | none (accepted) | — | normal 200 |
| Unknown `kid`, refresh times out / can't resolve | `AuthRequiredError("invalid_token")` | `verify_jwt` after `to_thread` timeout | 401 `invalid_token` (returns within `SUPABASE_JWKS_TIMEOUT_S`) |
| JWKS warm fails at startup | logged warning, non-fatal | lifespan startup | app starts; first request lazily fetches |
| Heal upsert DB error / race | caught + logged (structured, `user_id` only) | `heal_user_identity` try/except | request still 200; `/me` serves verified claims |
| DB or Redis down | flag set to `"error"` | `health.py` probe (timeout) | 200 with `{db:"error", …}` |

# Review lenses (pre-answer)

- **Scope / strategy.** Minimum viable: builds on the existing scaffold (17 models, tags slice, health,
  docker-compose) — adds only the auth spine + Alembic + verify harness. No new services/abstractions; the
  verifier is one Focal-local module (shared extraction deferred). Reversible: slices 1–2 are pure infra;
  the demo→real swap (slice 4) is a one-line dependency change to revert.
- **Architecture.** One verification path (`get_current_user`); `app_metadata`-only authz; membership/tenant
  logic untouched (no domain features here). Unhappy paths are enumerated in the error map above — every
  failure is a typed `AppError` mapped by the existing single handler, never a raw `HTTPException`.
- **Design.** Backend-only; no UI (login lives in the host per SHELL_CONTRACT.md). N/A.
- **DevEx.** `make verify` is the single entry point; `.env.example` documents `SUPABASE_URL` +
  `SUPABASE_JWKS_TIMEOUT_S`; the ES256 test fixture lets any contributor run the auth suite with no live
  Supabase. Local dev keeps the local-Docker Postgres/Redis loop (kept-deviation, per the task).

# Risks & migrations

- **Python 3.14 / dep-floor bump** (already landed) — `uv.lock` exists but predates the bump; regenerating
  it could surface a resolver change. Mitigation: `uv lock` + `uv sync --frozen` + full `make verify`
  locally before slice 1 merges.
- **Shared-DB Alembic safety (data-loss class)** — the canonical DB holds every app's schema, so a bare
  `include_schemas=True` would make autogenerate propose `DROP` for `prima.*`/`auth.*`/`billing.*`. Focal's
  `include_name` filter (slice 2) scopes autogenerate/check to `focal` only. **Prima's `env.py` currently
  lacks this filter** — flagged separately (out of scope here). Empty-DB safety: focal's `env.py` creates
  the `focal` schema before migrating, so `upgrade head` doesn't depend on `db/init.sql`.
- **Developer-generated Alembic baseline** — Claude lands config (`env.py` + `script.py.mako`) + models; the
  developer autogenerates and commits the baseline. Drift is guarded by `alembic check` (developer step +
  planned CI per root CLAUDE.md) — **not** by `make verify`, which stays ruff + mypy + pytest.
- **No FK from `focal.users` → `auth.users`** (decision above) — possible orphan rows; accepted for the
  foundation, flagged for §6. Rollback: the whole slice is additive — revert the deps swap to fall back to
  the demo path; infra slices (lockfile/Alembic/Makefile) are independently safe.
- **Client regression at the demo→real swap** — the client switches to `Authorization: Bearer` (token from
  the host-provided shared session; **never minted client-side**, per AUTH_FLOWS.md) in the **same** slice
  (4). Standalone-dev keeps the Tags page working via the server's env-gated `FOCAL_DEMO_AUTH` bypass (off
  by default) until the shell supplies the real session. Both server and client tags tests gate the slice.
