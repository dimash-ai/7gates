# Goal

Bring the new Focal **Tasks** page to old-focal task parity (focal-parity epic, slice 4). Today it is
a read + quick-add + delete + complete-toggle list: the edit pencil is hardcoded `disabled`, there is
no create/edit dialog, no detail dialog, the "Filter" button toggles nothing, and there is no
schedule-to-calendar or tag creation. Restore the full task editing + filtering
surface against the binding spec `apps/old-focal` (`TaskDialog`, `TaskInfoDialog`, `Tasks.tsx`).

# Scope

- `TaskDialog` (create + edit) over existing task fields: title, notes/description, due date + due
  time, project → product → activity cascade, tag (single, with inline tag-create), participants.
- `TaskInfoDialog` (read view + actions: edit, delete, toggle complete, inline date change).
- Filter/search panel: keyword search + project-type / sphere / project / product / activity / tag
  (incl. no-tag) multi-selects + date presets + custom range, with `localStorage` persistence.
- Schedule-a-task-as-event action (the dialog's `onScheduleAsEvent` → calendar).
- Everything consumes the already-landed slice-2 `canEdit` gating + `calendarId` scoping.
- **Backend handoff (the one non-frontend part):** task **recurrence** (none/daily/weekly/monthly/
  yearly) and **multi-participant** (`contactIds[]` + `otherParticipants`) — absent from the new
  FastAPI task model/schema — as a SQLAlchemy model + Alembic migration + schema/service + `gen:api`,
  then wired into the dialog.

# Out of scope

- AI-assistant header button (slice 12), offline/optimistic mutations (slice 11), dragging a task
  onto the calendar grid (calendar task panel, slice 6). The Tasks list is sorted via `taskSort`,
  not user-reorderable — there is no drag-drop on the Tasks page.
- Manual priority field — old-focal removed it (priority is auto from project type).
- Event custom-recurrence with interval (an events concept; tasks have only the 5 simple recurrences).
- Auth/landing (shared `@allosta/auth`).
